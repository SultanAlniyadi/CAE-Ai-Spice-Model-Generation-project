# Test Author Subagent Implementation Plan

## Goal and Boundaries

Implement a test-author subagent that turns source-supported modeling requirements into a ranked, executable acceptance suite before the device model exists. Follow the existing thin-agent/canonical-skill pattern. Support operational amplifiers and voltage supervisor/reset ICs only, matching `skills/requirement-definition/SKILL.md`.

This implementation is a reusable agent source artifact for distribution across workspaces, not an instruction to register or activate an agent in this workspace. Keep source authoring, packaging and downstream host registration distinct. Source files must contain no machine-specific paths and must document how consumers resolve the canonical skill after installation.

The user approved: authoring after extraction, explicit approved accuracy budgets for typical evidence, core functional acceptance gates, PySpice circuit construction with isolated ngspice batch execution, author-defined terminal contracts, limited harness smoke checks, versioned self-contained suites, partial delivery with explicit blockers, and minimal reusable helpers.

Do not implement the modeler/tester or tuning loop, rewrite `agents/ruthless-orchestrator.md`, modify upstream extraction/requirements contracts, relocate existing agents, or read/change the scheduled-for-deletion `spice-model-selector.md`. Treat unrelated orchestrator template roles as nonbinding project context.

## Existing Contracts

- `agents/requirement-definition.md` delegates to `skills/requirement-definition/SKILL.md`, with a canonical-file fallback. Its required-data report selects individual `NEEDED` items but deliberately contains no electrical values; its missing-data report identifies genuinely absent evidence.
- `agents/data-extractor.md` delegates to `skills/chart-data-extractor/SKILL.md`. Extraction workbook schema `1.0.0` includes Handoff, Metadata, Conditions, Specifications, Pins, Test_Circuits, Quality, Curve_Data, Fitting_Data and Validation. Numerical blanks are not zero. Pins describe physical mapping, not SPICE terminal order. Validation rows are proposals, not completed tests. Holdouts have `Fit_Eligible=0`.
- Requirement items have no stable machine IDs. Assign suite-local deterministic requirement IDs from named item, variant and source locator; retain the original locator and reconcile ambiguity explicitly rather than using Markdown row position.
- Existing agent sources are under `agents/`. The user's desired reusable-source destination is `agents/test-author.md`, distinct from a consumer's local registration directory. However, the current higher-priority instruction says to put new agents in `.mplab-ai/` without a reusable-source exception. Therefore author the portable source at `.mplab-ai/agent/test-author.md` for this implementation; do not treat this placement as proof of runtime registration. Using `agents/test-author.md` requires an explicit change or exception to that instruction, not merely different wording in this plan. Keep the canonical skill in `skills/test-author/SKILL.md` with discovery fallback and no user-specific installed paths.

Reusable agent source artifacts may live in the repository's established source directory, including `agents/`. Follow the repository's packaging conventions and the user's specified destination." This is a proposed policy, not an override of the current instruction. Installing, enabling or registering the reusable artifact in consuming workspaces is separate from authoring it and remains out of scope here.

## Ordered Implementation Tasks

1. **Author the reusable thin agent and canonical skill.** Add the portable source artifact `.mplab-ai/agent/test-author.md` with subagent metadata, bounded authoring/simulator-check permissions, role exclusions and a concise handoff. Do not add activation settings, install global files or assume that authoring registers the agent. Load `test-author` first; read `skills/test-author/SKILL.md` relative to the consuming repository root if discovery is unavailable, and block if neither works. State that consumers must install/discover the canonical skill or preserve this repository-relative layout. Put all detailed procedures, schemas, family coverage and failure rules in the skill. Add a reusable command artifact at `.mplab-ai/command/test-author.md` following the existing `subtask: true` convention, carrying inputs, scope and destination through without embedding a second workflow; downstream command registration remains separate.

2. **Define and validate the input contract.** Require a complete readable datasheet PDF, its required-data report and schema-1.0.0 extraction workbook. Accept the missing-data report, supporting documents, explicit user requirements, approved model-accuracy budgets, target/variant/package/channel/scope, simulator requirements and a supplied model-interface contract as additional inputs. Reconcile part identity, revision/hash, source locators, applicability, sheet schema and referenced IDs. Review applicable PDF content/footnotes and all supplied requirements; do not limit coverage to workbook Validation proposals. Stop without publishing a suite for missing mandatory inputs, unsupported family/schema, identity conflicts or unusable core artifacts.

3. **Reconcile evidence and build a coverage ledger.** Consume selected requirements, workbook Validation proposals, pins, conditions, source bounds, circuits, curves and Quality records. Map every in-scope behavior/user requirement to tests or a reasoned blocked/excluded record. Use extracted numerical evidence rather than re-digitizing or changing upstream files. New supporting-document numerical evidence or omissions generate precise extraction requests to the parent. User-supplied requirements/accuracy budgets may define criteria, but label them separately from datasheet evidence. Preserve conflicting evidence; do not silently choose favorable limits. Out-of-scope new requirements require scope reconciliation, not silent expansion.

4. **Define the versioned acceptance contract.** Use a JSON manifest as the source of truth, with a readable Markdown rendering. Give each test a deterministic ID, requirement and source/workbook references, behavior/family, applicability, analysis, full conditions/stimulus/fixture, metric definition and units, reference data, comparison operation, numeric criteria, tolerance provenance, priority, acceptance role and rationale, prerequisites, readiness and validation provenance. Keep priority (`critical/high/medium/low`) independent from acceptance role (`blocking/advisory`). Core in-scope functionality and explicitly mandatory user requirements gate acceptance; classify remaining fidelity checks individually. Bounds apply only at their documented conditions and evidence class. Typical observations are not guaranteed limits; require explicit approved model-accuracy budgets before assigning pass/fail criteria. Extraction uncertainty remains a distinct geometry envelope, not an automatic model budget or statistical confidence. Make any uncertainty/budget combination explicit and approved. Do not interpret absolute maximum ratings as functional guarantees.

5. **Implement conditional family procedures.** Select tests by documented features and requested scope, not a mandatory generic catalog. For op-amps consider basic polarity/closed-loop function, DC offset and bias conventions, gain/frequency response and stability conditions, directional slew, settling, output swing/current/loading, supply current, common-mode/supply rejection, and optional noise/temperature/shutdown behavior. Respect voltage- versus current-feedback topology and documented fixture/noise-gain definitions. For supervisors consider threshold crossings and hysteresis with direction, reset polarity and output topology/pull-up/load, assertion/release timing, startup/brownout/power sequencing, manual reset/enable/watchdog only when present, documented pulse filtering, and supply/output validity ranges. Do not invent powered-off behavior, hard clamps, undocumented timing or feature support. Specify measurement windows, initial states, crossing/event definitions, sweep direction, load and numerical resolution checks so criteria are reproducible.

6. **Define the pre-model interface and suite layout.** Honor a supplied verified interface; otherwise derive a logical ordered terminal contract from verified pin evidence, including channel, shared supplies, modes, exposed-pad applicability and reset topology. Distinguish physical pin mapping from SPICE order; escalate ambiguous choices. Record the proposed contract for orchestrator acceptance and require the later modeler to honor it. Generate a new uniquely versioned directory, defaulting beside the input workbook, never overwrite an existing suite, and honor an explicit destination only if available. Stage and validate before publishing; remove only incomplete outputs owned by this run. Include `manifest.json`, `interface.json`, `test-plan.md`, `benches/`, a Python runner with its minimal local helpers, frozen `references/` data, separate `fixtures/` for harness checks, dependency/run instructions, and harness-validation evidence. Copy only referenced evidence into the suite with provenance, preserve holdout/fitting labels, and hash immutable suite assets. Do not present already-used fitting evidence as independent holdout validation; interpolation cannot cross gaps or extrapolate undocumented regions.

7. **Add minimal reusable templates/helpers.** Place schema/template, runner and criterion logic under `skills/test-author/` using `templates/`, `scripts/` or `references/` as appropriate; generate device-specific benches per run. Avoid a general modeling framework. Use PySpice for circuit construction/deck generation and isolated ngspice batch subprocesses for execution, not the shared-library backend. Keep measurement definitions and thresholds authoritative in the manifest, not duplicated inconsistently in code. Support explicit interval/one-sided/absolute/relative/curve-error criteria as needed; define near-zero, phase wrapping, log-axis, sign and unit semantics. Missing/NaN/nonfinite results, absent events or insufficient sampling are not passing values. Use argument arrays and safe paths, deterministic outputs, per-test configurable finite timeouts, process cleanup, preserved logs and numerical traces. Preflight Python/PySpice/ngspice dependencies and record actual versions/features; do not silently install software or assume XSPICE availability. Document a finite default timeout as harness policy, distinct from the future modeler's iteration limit. Results live in a separate run directory; repeated execution never modifies criteria or references.

8. **Implement status, aggregation and parent handoff.** Separate authoring readiness (`ready`, `blocked`, `out_of_scope`), harness-check status and actual DUT results (`not_run`, `pass`, `fail`, `error`, `timeout`, `blocked`). A suite can be partially authored and still publish blocked test records, missing prerequisites and prioritized requests. Missing dependencies may yield an explicitly unverified suite, never a claim of executable validation. All ready DUT tests start `not_run`; fixture outcomes are never DUT outcomes. Acceptance is rejected when a blocking test fails, unresolved when required gates remain unrun/blocked/error/timeout, and accepted only when every required gate passes. Advisory failures remain visible. Return suite path/version/hashes, target/scope/interface, counts by readiness/priority/role, harness checks actually performed, coverage gaps and precise requests to the orchestrator. Treat the suite as frozen during fitting; changes require explicit reauthoring/new version, not modeler edits or relaxed thresholds.

9. **Validate implementation and portability.** Add small automated contract/criterion tests and representative synthetic evidence fixtures for both families. Verify metadata, canonical-skill fallback and command handoff contracts. Test repository-relative resolution from a different workspace root without machine-specific paths. Treat actual host discovery/command routing as a consuming-workspace integration check, not a requirement to activate this workspace's agent; file presence alone does not prove registration. Document the unresolved integration prerequisite: the current template orchestrator's task allowlist does not permit this agent and needs a later deliberate update. Do not rewrite it as part of this work. Smoke-test the batch runner where ngspice is available and report missing dependencies explicitly; never claim real-device validation without a real model.

## Validation Cases

- Input/provenance: absent PDF/report/workbook; unsupported family/schema; wrong variant/hash; broken joins; ambiguous pins; conflicting conditions; supporting evidence not yet extracted; unchanged upstream artifacts.
- Criteria: approved bounds versus typical targets; absent budget leaves a criterion blocker; blank versus zero; signed current/dB/phase/noise-unit handling; near-zero relative error; inclusive boundaries; missing events/nonfinite output; curve segments/gaps and holdout provenance.
- Acceptance: priorities independent from gates; blocking failure rejects; blocked/unrun/error/timeout gates cannot accept; advisory failure is reported without overriding passed gates; partial suites retain all coverage gaps.
- Benches: representative op-amp DC/AC/transient and supervisor threshold/hysteresis/timing/output-topology cases; terminal ordering and conditions match the manifest; insufficient time/sweep resolution is detected rather than silently passing.
- Harness smoke checks: known-result voltage-divider/simple terminal-compatible fixtures exercise expected pass and fail paths; malformed deck exercises error reporting; controlled subprocess exercises timeout/cleanup. Synthetic fixtures need not emulate the device and remain clearly separate from model deliverables.
- Publication/execution: directory collisions preserve existing content, failed generation does not publish an apparently complete suite, paths with spaces work on Windows, repeated execution writes separate results, manifest/reference tampering is detected, and the exported suite does not depend on the skill's installed location.

## Risks and Deferred Integration

- The extractor wrapper currently limits numerical evidence to the datasheet, despite the planned overall workflow accepting other documents. Return supporting-document extraction needs; extending that upstream capability is a separate change.
- Actual PySpice/ngspice feature support must be checked, not inferred from package presence. Shared-DLL installation is not required for the chosen batch path.
- Open-loop/stability and supervisor state/timing fixtures can be physically misleading if definitions or initial conditions are guessed. Block unresolved fixtures and test metric logic explicitly.
- A source limit is a contract for a device characteristic, not proof that a nominal behavioral model represents process corners. Preserve the approved modeling scope and never claim coverage of unsupported corners.
- File hashes enforce reproducibility/detect accidental changes, not adversarial security. Orchestrator policy must later enforce frozen suites during tuning.
- Reusable source packaging does not itself grant an exception to the current agent-placement instruction. The desired `agents/test-author.md` destination is deferred pending an explicit higher-priority exception; downstream installation/registration is also deferred.
- No remaining user-design questions block implementation. Host discovery, simulator availability and evidence-specific gaps are verification tasks or explicit blockers, not permission to broaden scope.
